## Testing the Auth Server for Access token using Postman:
* ![Postman vs Backend to Backend.png](images/Postman%20vs%20Backend%20to%20Backend.png)
* Well in case of getting the Access token using Postman we will recreate or simulate the behaviour of a normal backend service .
* For this first we will have to send a post request to the URL of the AuthServer which verifies the creds and grants access token.
* And while sending the POST Request we will have to make sure we are sending the details in the ``x-www-form-urlencoded`` format.
* After we receive the access token back after verification then we can use the same token to access our resource Server.
* While in case of Backend to Backend communication all the above steps are done automatically with the help of certain dependencies which need to be added.
* Backend Service A will automatically load the client_id and the client_secret in the POST Request to the auth server and once it receives a positive response then it will also send the request to the Resources Server along with the token.
* ``End-Point URL for the access token``: To get the endpoint URL for getting the access token .
  * First login into your KeyCloak realm .
  * ![img_23.png](images/img_23.png)
  * Then select the Realm Settings and then click on the OpenID Endpoint Configuration link.
  * ![img_24.png](images/img_24.png)
  * ![img_25.png](images/img_25.png)
  * If you see here then there are so many endpoints here , from these we need to invoke the token_endpoint since we are expecting a access token.
  * ![img_26.png](images/img_26.png)
  * We copied the token_endpoint now we are going to send a POST request here via the POSTMAN and as can be seen above we have a body in the x-www-form-urlencoded .
  * We have some Key and Value as can be seen .
  * we mentioned he grant_type which is going to be client_credentials so that the endpoint knows by which way it has to verify.
  * Then we have given it the client_id which was set by us only in the clients of the Respective realm of the Keycloak.
  * Then we have the client_secret which was generated and give to us by the Keycloak itself if you remeber.
  * And then we have mentioned the scopes which means what are the things that we are requesting the keycloak server other than the access token.
